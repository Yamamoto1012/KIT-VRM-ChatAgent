# [バグ修正] VoiceChatモード音声入力・AI回答バグ修正
---

## 1. 背景 (Background)

* **なぜこのタスクが必要か？** VoiceChatモードにおいて、ユーザーが適切に音声対話を行えない重大なバグが発生している。
* **現状の課題:** 
  * ユーザーの音声入力待ち時間が1.5秒と短すぎて、話の途中で強制的に音声認識が停止してしまう
  * AIからの回答が返ってこない（空文字列や古い値が表示される）
  * 音声認識のspeechendイベントが予期せず発火し、ユーザーがまだ話そうとしている最中でも認識が終了してしまう
* **達成したいこと:** ユーザーが自然な速度で話すことができ、AIからの回答が確実に返ってくる、使いやすいVoiceChatモードを実現する
* **関連資料:** 
    * - [VoiceChat実装](mdc:frontend/src/features/VoiceChat/)
    * - [音声認識フック](mdc:frontend/src/features/VoiceChat/useVoiceChat.ts)

## 2. 詳細 (Details)

* **何を実装するのか？** VoiceChatモードの音声入力タイミングとAI回答生成の根本的なバグを修正する。
* - [ ] 要件1: 無音タイムアウト時間を1.5秒から3-4秒に延長し、ユーザーが自然に話せるようにする
* - [ ] 要件2: speechendイベントでの自動停止を削除または条件付きにして、意図しない停止を防ぐ
* - [ ] 要件3: AIのストリーミング応答が正しく蓄積され、最終的な回答として表示・音声再生されるように修正する
* - [ ] 要件4: 処理状態の適切な管理により、ユーザーに分かりやすいフィードバックを提供する

## 3. 完了の定義 / 終了要件 (Definition of Done / Acceptance Criteria)

* **何をもって「完了」とするか？** このタスクの完了を客観的に判断するための基準を、テスト可能な項目として具体的に記述する。
* **機能要件:**
    * - [ ] ユーザーが3秒以上の間を空けて話しても音声認識が継続されること
    * - [ ] speechendイベントによる意図しない音声認識停止が発生しないこと
    * - [ ] AIの回答が確実に表示され、音声でも再生されること
    * - [ ] ストリーミング中の応答が正しく蓄積され、完了時に正確な内容が保存されること
    * - [ ] 処理状態が適切に更新され、ユーザーに現在の状況が分かること
* **非機能要件:**
    * - [ ] 音声認識の応答性が維持されること（過度に長いタイムアウトにならないこと）
    * - [ ] Vitest + Testing Libraryによる単体テストが実装され、すべてパスすること
    * - [ ] 修正によるパフォーマンス劣化が発生しないこと

## 4. 実装方針 (Implementation Plan)

* **どのように実装するか？** タスクを達成するための技術的なアプローチや具体的な手順を記述する。
* **影響範囲の調査:**
    * - 修正: `src/features/VoiceChat/VoiceChat.tsx` (45-58行目の無音監視、172-174行目のAI応答処理)
    * - 修正: `src/features/VoiceChat/useVoiceChat.ts` (54行目のonspeechendハンドラー)
    * - 確認: `src/store/voiceChatAtoms.ts` (状態管理の妥当性確認)

* **実装ステップ:**
    1. **音声入力タイムアウト修正:**
        * VoiceChat.tsx の無音監視タイムアウトを1500ms → 3500msに変更
        * 300ms間隔のチェック頻度を500ms間隔に調整してパフォーマンス向上
    2. **speechend自動停止の修正:**
        * useVoiceChat.ts の`recognition.onspeechend`ハンドラーを削除
        * または条件付き実行（連続無音時間が一定以上の場合のみ停止）にする
    3. **AI応答蓄積の修正:**
        * `accumulatedResponse`のstate更新をリアルタイムで追跡できるように修正
        * `useCallback`の依存配列から`accumulatedResponse`を削除し、refを使用するか、ストリーミング完了時に最新値を取得
        * ストリーミング完了の`done`チャンクで最終応答を処理するように変更
    4. **状態管理の改善:**
        * 処理状態の遷移をより明確にし、エラーハンドリングを強化
        * VRM思考状態との連携を改善
    5. **テスト実装:**
        * 音声認識のタイムアウト動作のテスト
        * AIストリーミング応答の蓄積テスト
        * エラー状態の適切な処理テスト

## 5. 備考 (Notes)

* **技術的な注意点:**
  * Web Speech APIの`speechend`イベントは ブラウザによって動作が異なるため、クロスブラウザ対応を考慮する
  * 音声認識のタイムアウト時間は、日本語話者の自然な話し方（間の取り方）を考慮して設定する
  * ストリーミング応答の蓄積処理では、メモリリークを防ぐため適切なクリーンアップを実装する
* **未確定な仕様:**
  * タイムアウト時間の最適値（3.5秒で開始し、ユーザーフィードバックに基づき調整）
  * speechendイベントの完全削除か条件付き実行かの選択（まず削除して動作確認後に判断）
* **関連タスク:**
  * MediaPipe連携での音声認識精度向上（将来的な拡張）
  * 多言語対応時の言語別タイムアウト調整（将来的な拡張）
